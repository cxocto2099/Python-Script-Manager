# Python Script Manager

一个轻量级的 Windows Python 脚本管理工具，支持同时运行和管理多个 Python 脚本，实时查看输出日志。

## 📖 项目背景

### 为什么重新开发？

这个项目最初是用 **VB6** 编写的，采用调用系统默认 CMD 窗口并隐藏的方式运行 Python 脚本。虽然功能可用，但存在以下问题：

1. **兼容性问题**：不同版本的 Windows 系统对 CMD 窗口的处理方式不同，导致行为不一致
2. **界面不美观**：多个 CMD 窗口即使隐藏也会在任务栏显示，切换和管理很不方便
3. **输出捕获困难**：通过重定向 CMD 输出来捕获日志，稳定性较差
4. **技术过时**：VB6 已经停止支持多年，维护和扩展困难

为了解决这些问题，我决定用 **纯 C 语言 + Win32 API** 重新编写这个工具，实现：
- ✅ 完全自主控制的进程管理
- ✅ 统一的界面展示所有脚本输出
- ✅ 更好的性能和稳定性
- ✅ 无需任何第三方依赖

## ✨ 主要特性

### 🎯 核心功能

- **多脚本管理**：同时运行和管理多个 Python 脚本
- **实时日志显示**：每个脚本的输出实时显示在独立的文本框中
- **快速切换**：点击列表即可切换查看不同脚本的日志，切换速度 < 2ms
- **启动/停止控制**：双击列表项即可启动或停止脚本
- **配置持久化**：自动保存脚本列表到 `scripts.ini` 文件

### 🔍 智能脚本发现

- **配置文件导入**：从 `scripts.ini` 加载已配置的脚本路径
- **自动扫描**：启动时自动扫描程序目录下的 `.py` 文件
- **来源标识**：列表中清晰区分 `[配置]` 和 `[本地]` 脚本
- **智能去重**：避免重复添加相同路径的脚本

### ⚡ 性能优化

- **独立控件架构**：每个脚本拥有独立的 EDIT 控件，切换时无需重新加载
- **智能节流更新**：自动平衡实时性和性能，高频输出时减少刷新频率
- **缓冲区管理**：自动清理旧数据，防止内存溢出（最大 1MB/脚本）
- **后台线程读取**：使用独立线程捕获输出，不阻塞 UI

### 🎨 用户体验

- **简洁界面**：左侧脚本列表，右侧日志显示，一目了然
- **状态指示**：运行中的脚本以绿色标识，停止的以红色标识
- **自动滚动**：新日志自动滚动到底部，保持最新内容可见
- **无控制台窗口**：Python 脚本在后台运行，不显示黑色 CMD 窗口

## 🛠️ 技术架构

### 核心技术栈

- **语言**：纯 C (C99)
- **平台**：Windows Win32 API
- **编译器**：MinGW GCC / MSVC
- **GUI**：原生 Windows 控件（EDIT、LISTBOX、BUTTON）
- **并发**：Windows 多线程（CreateThread + CriticalSection）

### 架构设计

```
┌─────────────────────────────────────────────┐
│           UI 主线程 (消息循环)                │
│  ├─ 窗口创建与管理                            │
│  ├─ 用户交互处理                              │
│  └─ EDIT 控件更新（智能节流）                 │
└──────────────┬──────────────────────────────┘
               │
┌──────────────┴──────────────────────────────┐
│         后台读取线程（每脚本一个）             │
│  ├─ ReadPipeThread                           │
│  ├─ 捕获 stdout/stderr                       │
│  └─ 更新 outputBuffer（临界区保护）           │
└──────────────┬──────────────────────────────┘
               │
┌──────────────┴──────────────────────────────┐
│         Python 子进程                         │
│  ├─ CREATE_NO_WINDOW（隐藏控制台）            │
│  ├─ 管道重定向输出                            │
│  └─ 支持 GUI 程序（PyQt5等）                  │
└─────────────────────────────────────────────┘
```

### 关键设计决策

#### 1. 独立 EDIT 控件 vs 共享控件

**选择**：每个脚本拥有独立的 EDIT 控件

**原因**：
- ✅ 切换速度极快（Show/Hide 只需 ~2ms）
- ✅ 无需每次切换时重新加载内容
- ✅ 每个脚本的状态完全独立

#### 2. 全量更新 vs 增量更新

**选择**：使用 `SetWindowTextA` 全量更新 + 智能节流

**原因**：
- ✅ 保证 EDIT 内容与 buffer 完全同步
- ✅ 避免增量更新导致的复杂同步问题
- ✅ 通过节流机制（100ms/4KB）平衡性能

#### 3. 进程启动方式

**选择**：`CREATE_NO_WINDOW` + 不重定向 stdin

**原因**：
- ✅ 隐藏控制台窗口（不显示黑色 CMD）
- ✅ 允许 GUI 程序（如 PyQt5）正常显示界面
- ✅ 避免 stdin 重定向导致的初始化问题

## 📦 编译与运行

### 前置要求

- Windows 7 或更高版本
- Python 3.x（需要添加到系统 PATH）
- C 编译器（MinGW GCC 或 MSVC）

### 编译步骤

#### 使用 MinGW GCC

```bash
gcc main.c -o PY_console.exe -mwindows -lcomctl32 -O2
```

#### 使用 Red Panda C++ IDE

1. 打开 `PY_console.dev` 项目文件
2. 点击 "编译" 按钮（F9）
3. 生成的可执行文件在输出目录

### 运行

直接双击 `PY_console.exe` 即可运行。

## 📝 使用说明

### 添加脚本

1. 点击 **"添加脚本"** 按钮
2. 选择要运行的 `.py` 文件
3. 脚本会添加到列表中（标记为 `[配置]`）

### 启动/停止脚本

- **双击** 列表中的脚本名称
- 运行中的脚本显示为 ● 绿色
- 停止的脚本显示为 ○ 红色

### 查看日志

- **单击** 列表中的脚本名称
- 右侧显示该脚本的实时输出
- 新日志自动滚动到底部

### 删除脚本

1. 选中要删除的脚本
2. 点击 **"删除脚本"** 按钮
3. 注意：只会从配置中移除，不会删除文件

### 配置文件

脚本列表保存在 `scripts.ini` 文件中：

```ini
[Scripts]
Count=3
Script1=D:\Projects\test.py
Script2=D:\Projects\demo.py
Script3=D:\Projects\app.py
```

## 🔧 高级配置

### 调整更新节流参数

如果需要调整 UI 更新的实时性，可以修改 `AppendToScriptOutput` 函数中的参数：

```c
// 时间阈值（毫秒）- 越小越实时，越大越省资源
(now - script->lastUpdateTime > 100)  // 推荐：50-200

// 大小阈值（字节）- 越小越实时，越大越省资源
(script->accumulatedBytes > 4096)     // 推荐：2048-8192
```

### 调整缓冲区大小

修改 `main.c` 顶部的宏定义：

```c
#define MAX_OUTPUT_SIZE (1024 * 1024)  // 默认 1MB
#define BUFFER_CLEAR_RATIO 2           // 清理时保留一半
```

## 🐛 已知问题

- **大文本性能**：单个脚本输出超过 500KB 时，刷新可能有轻微延迟（已通过节流优化）
- **中文编码**：Python 脚本输出需要使用 UTF-8 或 GBK 编码
- **特殊字符**：某些 ANSI 转义码可能无法正确显示

## 📚 开发笔记

### 关键技术点

1. **管道重定向**：使用 `CreatePipe` 捕获子进程的 stdout/stderr
2. **临界区同步**：使用 `CriticalSection` 保护共享缓冲区
3. **智能节流**：平衡实时性和性能，避免频繁 UI 更新
4. **GUI 程序支持**：特殊处理 PyQt5 等 GUI 程序的窗口显示

### 常见陷阱

- ❌ 不要在临界区内调用 `SendMessage`（可能导致死锁）
- ❌ 不要使用 `SW_HIDE` 启动 GUI 程序（会阻止窗口显示）
- ❌ 不要重定向 stdin（某些 GUI 程序初始化会失败）
- ✅ 使用 `CREATE_NO_WINDOW` 隐藏控制台但允许 GUI 显示
- ✅ 设置 `si.hStdInput = NULL` 避免 stdin 问题
